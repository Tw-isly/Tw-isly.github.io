使用 Codex 时，影响效率的往往不只是等待回答的时间，还包括反复解释需求、寻找合适的工具、复制资料，以及交付后重新调整格式。Skills 可以把这些重复步骤整理成可复用的工作流程，让 Codex 更容易选对工具、按要求执行，并交付可以继续使用的成果。

这篇文章整理了 10 个实用技能。前五个侧重工具选择、流程复用和 Codex 使用，后五个侧重资料与办公成果。每个技能都附有功能说明、使用场景和可直接改写使用的提示词。

## 先理解 Skill、插件与工具的关系

**Skill 是工作方法。**它通常由 `SKILL.md` 和可选的脚本、参考资料、模板等组成，说明什么时候使用、如何完成任务，以及结果应满足哪些要求。

**插件是能力的安装与分发载体。**一个插件可以包含多个 Skills，也可以连接外部服务，提供读取数据或执行操作的工具。例如，处理 Google Drive 文件既需要正确的流程，也需要已经连接的账户和相应工具。

因此，技能已经可用，并不代表所有外部账户都已连接；安装技能也不会自动获得文件访问权限。官方文档对两者的职责有进一步说明：[Skills 与工具的关系](https://developers.openai.com/plugins/concepts/skills)。

### 如何调用

最容易使用的方式是在任务里直接写出技能名称和具体目标：

```text
使用 plugin-management，为我的资料整理任务选择合适的插件，优先使用已有连接。
```

对于系统技能，也可以使用 `$skill-creator` 这样的显式调用方式。技能名称明确、任务匹配时，Codex 更容易选中对应流程。自然语言任务也可能自动触发适用技能；遇到同名技能时，可以补充插件名称，例如 `google-drive:google-drive`。

### 本次整理时的安装状态

截至 2026 年 10 月 11 日，在这次核对的 Codex 环境中，下列 10 个技能均已提供且对应技能文件存在。其中 `skill-creator`、`skill-installer`、`openai-docs` 是系统内置技能，其余来自当前的插件或文档工具包。因此，这个环境无需再复制安装一遍。

这是一份当前环境的核对结果，不代表所有人的 Codex 默认拥有相同技能。更换设备或环境后，应重新确认技能列表和服务连接状态。

| 技能 | 主要用途 | 典型成果 |
| --- | --- | --- |
| plugin-management | 选择插件、了解权限与依赖 | 合适的插件建议与连接说明 |
| skill-creator | 固定常用工作流程 | 个人可复用技能 |
| template-creator | 固定参考成果的结构与风格 | 个人模板技能 |
| skill-installer | 查找和安装新的技能 | 已安装的技能目录 |
| openai-docs | 查询官方 OpenAI 使用资料 | 有来源的使用指导 |
| google-drive | 发现、读取和整理云端资料 | 资料清单、摘要或文件更新 |
| Spreadsheets | 制作与修改表格 | 可编辑的表格、公式和图表 |
| documents | 制作与编辑 Word 文档 | 排版经过检查的 DOCX |
| Presentations | 制作与修改演示文稿 | 可编辑的 PPTX 或 Slides |

## 1. plugin-management：先选对插件

### 功能

这个技能帮助 Codex 判断任务是否需要外部服务，发现合适的插件，并查看插件权限和依赖。它会优先考虑已有工具与已连接插件；遇到确实缺少的能力，再查找新的集成。

它尤其适合“我知道要完成什么，但不知道该用哪个插件”的情况。插件建议本身不会自动完成账户连接，实际操作仍需对应插件的工具可用。

### 使用场景

整理邮箱和日历、汇总项目管理系统里的任务、寻找能读取团队资料的服务，或者检查某个插件为什么无法执行操作。这里的价值在于减少自行寻找插件和反复尝试的时间。

### 使用方式

提供任务、资料来源，以及是否允许修改数据。可以先要求比较能力，再执行已经明确授权的操作。

```text
使用 plugin-management，判断整理我的项目资料需要哪些插件。
资料可能在 Google Drive 和 GitHub 中，优先使用已经连接的插件。
列出各自能处理的内容；如果还缺连接，请说明缺哪一步。
```

## 2. skill-creator：把重复流程变成个人技能

### 功能

`skill-creator` 用于创建或更新 Codex 技能。它可以把你的任务规则、输入要求、操作步骤和交付标准整理成 `SKILL.md`，必要时加入脚本或参考资料。

适合写进技能的是能改变工作结果的具体规则，例如博客的分类方式、项目资料存放位置、数据统计口径。泛泛的“认真工作”“提高效率”很难形成可执行的流程。

### 使用场景

每周重复整理周报，每次写文章都要交代格式，或定期处理一批相似的数据。一个成熟的个人技能可以减少后续重复提示，也便于维护流程。

### 使用方式

说明技能名称、触发场景、输入、输出，以及有实际意义的限制。首次创建后，用一个真实任务检查它是否符合习惯。

```text
$skill-creator
创建一个名为 study-note 的个人技能。
用于把我的编程学习记录整理为 Markdown 笔记。
输出包含问题、核心知识、最小示例和常见错误，保留原始代码的含义。
只有我明确要求发布时才执行发布；普通整理任务只生成笔记。
```

## 3. template-creator：保存满意成果的结构与风格

### 功能

这个技能从一份参考成果创建可复用的个人模板技能，保留参考文件、结构和风格信息。可用参考包括 Word、PPT、Excel、原生 Google Workspace 文件，以及支持的图片、邮件文本和 Sites 项目等。

它和 `skill-creator` 的侧重点不同：前者以参考成果为依据，重在复现样式与结构；后者重在定义任务流程和判断规则。模板技能默认保存在个人技能目录中，并不等于上传或发布一个团队插件。

### 使用场景

复用已经满意的周报、汇报 PPT、预算表或邮件风格。尤其适合“内容每次变化，但版式和表达方式基本固定”的工作。

### 使用方式

提供一份明确的参考文件或可访问的原生 Google 文件链接，说明以后要复用哪些特点。创建完成后，后续应调用生成的模板技能名称。

```text
使用 template-creator，把我附上的 weekly-report.docx 做成个人周报模板技能。
保留标题层级、表格样式和正文语气，将日期、进展、问题和下周计划作为可替换内容。
```

本地创建通常需要实际参考文件；一段笼统描述无法完整表达原文件的版式。Google 文件参考还需要相应访问权限。

## 4. skill-installer：查找和安装新技能

### 功能

`skill-installer` 可以列出精选技能，也可以从指定 GitHub 仓库路径安装技能。它负责把技能及相关文件放入个人技能目录，默认位置为 `$CODEX_HOME/skills`。

系统内置技能通常无需再次安装。插件提供的技能也应先检查当前是否已经可用，避免同名副本增加维护负担。

### 使用场景

更换环境后补齐工具，安装某个已经选好的技能，或者引入团队维护的技能仓库。它提供的是安装流程；判断某个技能是否适合自己的任务，仍需要看功能、来源和使用条件。

### 使用方式

先查看候选项，再给出明确的技能名称或仓库路径。

```text
$skill-installer
列出精选目录中可安装的技能，并标出已经安装的项。
重点介绍适合资料整理和软件开发的技能。
```

指定来源时，可以写：“使用 skill-installer，安装这个 GitHub 链接对应的技能。”新安装的技能通常在下一轮对话中可用。这个技能不会代替 Google、GitHub 等服务的账户授权。

## 5. openai-docs：用官方资料处理 Codex 问题

### 功能

这个技能适用于 Codex 设置、模型选择、技能、自动化、故障排查，以及 OpenAI API 等问题。它会根据问题查询官方资料，给出有来源的说明，并区分已经确认的事实和资料尚未覆盖的部分。

对于经常变化的产品功能，先核对资料能减少按照过时教程操作的成本。它的价值是提高使用指导的可靠性，不是自动修改所有设置。

### 使用场景

不知道如何选择模型、想了解定时任务、某个功能与教程描述不一致，或者准备开发调用 OpenAI API 的程序。

### 使用方式

描述具体任务和遇到的问题，尽量保留功能名称、错误提示或相关设置。

```text
使用 openai-docs，查询 Codex 当前关于模型选择和推理设置的官方说明。
我的任务主要是小型代码修改和博客写作，希望减少等待。
请说明各设置的取舍，并给出支持结论的官方链接。
```

若资料无法确认某个账户是否具有功能，应结合当前账户状态核实，不能仅凭文档假定已经开通。

## 6. google-drive：统一处理云端资料

### 功能

`google-drive` 是 Google 文件工作的统一入口，可用于查找文件、读取内容、检查元数据，以及复制、移动、导出和管理共享等任务。涉及 Docs、Sheets、Slides 的具体内容编辑时，它会转入相应的专门技能。

先发现并确认文件，再操作内容，可以减少误选版本或文件的情况。用户不需要为 Docs、Sheets、Slides 分别寻找独立插件。

### 使用场景

整理课程资料、搜集项目文档、比较文件版本，或者将多份材料汇总成带来源的摘要。

### 使用方式

给出文件链接、文件夹或足够明确的搜索范围，并说明希望读取、整理还是修改。

```text
使用 google-drive，查找“课程项目”文件夹中的项目方案和会议记录。
按文件整理目标、当前进展和待办事项，附上原文件链接。
这次只读取和总结，不移动文件或更改共享权限。
```

前提是 Google Drive 连接已经完成，当前账户能访问目标文件。技能可用本身不会扩大访问范围。

## 7. Spreadsheets：交付可以继续编辑的表格

### 功能

这个技能用于创建、修改和分析 `.xlsx`、`.xls`、`.csv`、`.tsv` 等表格，处理公式、格式、图表和计算结果。Google Sheets 目标也可以结合 Google Drive 的对应流程完成。

好的表格任务应交代数据含义、单位和统计方式。例如，支出按支付日期还是账单月份统计，会直接影响结果。要求保留原始数据并标明处理方法，有助于后续核对。

### 使用场景

学习计划、消费记录、预算与实际对比、项目进度表，或把零散数据整理成汇总表与图表。

### 使用方式

提供源数据，说明计算规则和最终要查看的结果。

```text
使用 Spreadsheets，把这些消费记录整理成 Excel。
保留原始记录，按月份和类别汇总，加入可更新的合计公式和月度支出图。
空金额标为缺失，不按零处理；最后检查汇总与原始记录是否一致。
```

它处理的是表格文件和相应工作流。若目标是实时控制已打开的 Excel 窗口，应使用相应的 Excel 实时控制能力。

## 8. documents：制作并检查 Word 文档

### 功能

`documents` 用于创建、编辑、批注和修订 Word 文档，并通过渲染检查分页、表格、文字和布局。它能把一段内容做成正式的 `.docx` 成果，让标题层级和版式便于后续编辑。

对于需要提交的文件，排版检查很有价值：纯文本内容正确，并不代表实际页面没有断行、表格截断或字体问题。

### 使用场景

课程报告、项目方案、正式说明文档、长篇材料整理，以及对已有 Word 文件进行定向修改。

### 使用方式

说明读者、文档目的、结构与格式；如果有参考模板，直接提供模板。

```text
使用 documents，把这些材料整理成课程项目报告，交付可编辑的 DOCX。
读者是任课老师，包含目标、方法、结果和局限，保留资料来源。
沿用我提供的模板，并检查分页、表格和中文字体显示。
```

若需要原生 Google Docs，可以结合 Google Drive 导入流程完成；本地 Word 文档生成和云端文件创建是两个步骤。

## 9. Presentations：从材料到可编辑的汇报稿

### 功能

这个技能用于读取、制作和修改 PowerPoint 或 Google Slides。它处理的不只是把段落分到不同页面，还包括内容组织、页面布局、视觉层级，以及已有模板的延续。

任务里明确听众和汇报目的，比单纯要求“做得好看”更有帮助。已有原生 Google Slides 的修改和模板跟随，需要结合 Google Drive 的 Slides 工作流。

### 使用场景

课程展示、项目答辩、阶段总结，以及将长报告改为适合口头讲解的演示文稿。

### 使用方式

提供材料、听众、时长和页数范围。如果有数据或图表，应说明是否允许重新绘制。

```text
使用 Presentations，把这份项目报告做成约 10 页 PPT，供 8 分钟课程展示使用。
先讲结论，再讲方法、结果和局限；图表注明来源，不补造数据。
沿用我附上的模板，交付可编辑的 PPTX 并检查文字和图表是否完整显示。
```

相比重复要求“再漂亮一点”，给出实际参考和具体修改点，通常更容易得到稳定的结果。

## 10. pdf：读取、制作和核对 PDF

### 功能

`pdf` 用于读取 PDF、提取文字与表格、制作文件、检查渲染，以及填写可交互的 PDF 表单。它会结合内容和页面检查，因为提取出的文字顺序不一定等于实际阅读顺序。

对于表单，还需要验证真正的字段值；页面看上去已填写，并不必然代表表单数据已经正确保存。

### 使用场景

阅读课程讲义、论文和手册，整理带页码来源的摘要，制作可打印文件，或填写已有的可交互表单。

### 使用方式

提供文件，指出关注的章节、表格或字段，以及结果应为摘要还是新的 PDF。

```text
使用 pdf，阅读这份课程讲义，整理核心概念、公式和容易混淆的地方。
每条关键结论注明 PDF 页码，区分原文内容和你的解释。
遇到图片中的文字或提取不完整的表格，请说明需要进一步核对的部分。
```

扫描件的提取效果取决于图像清晰度及可用的识别工具，不能假定任何 PDF 都能无损转成结构化数据。

## 怎样把这些技能组合起来

### 资料整理与报告

先用 `google-drive` 找到原始文件，用 `pdf` 阅读其中的讲义或报告；有定量数据时交给 `Spreadsheets`，最后用 `documents` 或 `Presentations` 制作交付文件。如果缺少资料来源的连接，再用 `plugin-management` 发现合适插件。

### 固定周报流程

先完成一份符合要求的周报，用 `template-creator` 保存结构和风格，再用 `skill-creator` 定义资料来源、整理规则与交付要求。两者是否都需要，取决于任务：只想复用版式时，模板技能就可能足够。

### 给任务写清楚交付标准

以下提示词结构可以直接套用：

```text
使用 [技能名称]，根据 [文件或资料来源] 完成 [具体任务]。
目标读者是 [谁]，输出为 [格式]。
必须包含 [关键内容]，沿用 [模板或风格]。
完成后检查 [计算、来源、排版或链接]。
```

Skills 更适合减少重复沟通和返工，不保证每次任务都更快。文件渲染、图表校验、服务请求等步骤可能增加等待，但也可能节省交付后的修改时间。可以用自己经常重复的任务比较：从提出需求到得到可用成果，需要多少时间、几轮修改，再决定哪些技能值得长期保留。

## 资料来源与适用范围

本文的具体功能根据当前环境提供的技能说明整理，示例提示词用于说明调用方式，不代表已执行这些示例任务。技能名称、工具支持和产品功能可能随版本变化。

- [OpenAI 官方：Skills 的组成与激活方式](https://developers.openai.com/plugins/concepts/skills)
- [OpenAI 官方：创建技能与 skill-creator](https://developers.openai.com/plugins/build/skills)

优先从一个常做的任务开始：明确需要调用的工具，写清交付标准，完成一次后再将有效流程保存为个人技能或模板。这样更容易判断效率到底改善在什么地方。
